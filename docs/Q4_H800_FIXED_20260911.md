# Q4 fixed PPU recipes replayed on H800

The H800 reproduces the **direction and a substantial magnitude** of the
K-pack/Xplane regression at M1/N5120/K8192. It does not establish identical
stall causality: NCU performance counters are not available in this container.

| Cache regime | Xplane FP32, us | K-pack FP32, us | Supplied raw-GGUF FP32, us | K-pack vs Xplane | K-pack vs raw reference |
| --- | ---: | ---: | ---: | ---: | ---: |
| warm | 16.164999 | 19.681999 | 19.195000 | +21.7569% | +2.5371% |
| rotating | 18.748344 | 22.570972 | 22.497830 | +20.3892% | +0.3251% |

For context, the earlier PPU rotating receipt was 22.9280 us Xplane versus
28.8857 us K-pack (+25.9845%). The RTX PRO6000 same-recipe rotating comparison
did not reproduce that gap (+0.0854%). H800 therefore provides a more useful
reproduction of this specific timing symptom, not universal PPU equivalence.

## Authority and limits

- GPU: NVIDIA H800 PCIe, 114 SMs, 52,428,800-byte reported L2; driver
  570.124.04, CUDA 12.8.93, compiled for `sm_90`.
- Same existing independent GGUF fixture, FP16-exact A, FP32 dot/reduction and
  FP32 output for all arms. Each process requires finite independent dot error
  below 0.005 and a zero-code negative with metadata unchanged.
- Xplane C2/W8/S1 and K-pack C4/W8/S1 are the PPU-selected recipes, not newly
  tuned H800 winners. Both have 320 CTAs of 256 threads.
- Raw reference uses C2/W8/K-warps1, also 320 CTAs of 256 threads. This is a
  fixed comparison, not a claim that this is its best FP32 configuration.
- Six alternating-order rounds x 15 graph samples per arm per cache regime.
  Five first graph replays are excluded. Warm uses one weight, 32 calls per
  graph; rotating uses five complete weight copies, 35 calls per graph, with
  total ring bytes at least 2.25 x L2.
- `gemv_ref.cu` retains its original raw-GGUF loads and FP16 dequantization,
  with all four inner dot chains, their fold, reduction and output changed to
  FP32. Its affine rounding differs from the canonical reader, so the raw
  comparison is not a pure layout ablation.
- AIU/swizzled-ldmatrix is not emulated or tested on H800. Its PPU package is
  a separate compile-only experiment until device admission.

## Compiler resource observations, not NCU counters

The exact selected H800 specializations compile as:

| Arm | Registers/thread | Spill loads/stores | Shared storage |
| --- | ---: | --- | --- |
| Xplane C2/W8 | 64 | 0 / 0 bytes | 16 KiB dynamic A |
| K-pack C4/W8 | 56 | 0 / 0 bytes | 512 bytes static reduction |
| Raw reference C2/W8 FP32 | 64 | 4 / 4 bytes | 16 KiB dynamic A |

Those are ptxas resource reports, not measured execution counts. In
particular, the converted raw reference has a small spill; it should not be
presented as an already-optimized FP32 implementation.

NCU rejects the first profiled arm with `ERR_NVGPUCTRPERM`; the host reports
`RmProfilingAdminOnly: 1`. No host driver/module or container privilege was
changed. There are **no H800 NCU utilization/stall numbers** in this result.
Permission denial does not invalidate the separately collected event timings.

## Reproduction

Use the same source tree and exported fixture:

```bash
python dev/gemv_cuda/build_fixed_reference.py \
  --cuda /usr/local/cuda --arch 90 --jobs 4 --output /path/to/new-build
python dev/gemv_cuda/run_fixed_reference.py \
  --build /path/to/new-build --fixture /path/to/q12-n5120-k8192-e1-c1.bin \
  --output /path/to/new-results
```

Optionally add `--ncu /usr/local/cuda/bin/ncu` only when counters are available.
The initial NVIDIA build exposed two compile-boundary issues, corrected only
in the development adaptation: PPU compiler macros are not injected into the
Xplane/reference units, and packed-half arithmetic constants use NVIDIA's
register-operand constraints. Neither change replaces FP32 accumulation or
changes the input format.
