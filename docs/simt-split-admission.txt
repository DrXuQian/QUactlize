SIMT common-reader Split-K admission (PPU 1.0)

Scope
  Before/after implementation comparison, not a new global selector sweep.
  Q2_K through Q6_K; dense, grouped and indexed; F32 input/output, with
  independent F16/BF16 activation computation and ordered FP32 accumulation.
  Q8 remains an optional separate experiment. Production defaults unchanged.

Frozen inventory
  70 previous non-Q8 families plus four shipping fixed-path controls (74).
  The previous 3 recipes per format (4 for Q4), each at S1/S2/S4/S8.
  2224 numerical pairs; 1776 paired cold timing cells. Basic fixtures test
  M1/M3/M8; large extensions retain M1/M8 or their original M8 coverage.
  No new Cartesian search; ten compiled objects/images, no TC rebuild.

Baseline and candidate
  Baseline follows current measured_decode_launch/launch_v2 for the recipe,
  including the Q4/Q5 model-specific bodies. It is NOT the previous Q6
  experimental A3 control and NOT a different best-of-config comparison.
  Candidate uses the earlier common sparse metadata/unsigned address body,
  with Split-K partition in grid.z. Canonical weight bytes and math order are
  unchanged. Both use the existing ordered reducer. No extra split-specific
  optimized body or public ABI is introduced by this experiment.

Evidence
  Official GGUF oracle for whole outputs and every partial partition at 16
  N positions; empty partitions, both weight addresses, changing activations,
  large BF16 inputs, exact before/after bits, guards and negative controls.
  Six alternating rounds x five samples, rotating active weight addresses
  covering at least 2.25 verified L2. Graph creation/upload/warmup excluded.
  One kernel type per timed interval: producer and reducer separately; the
  identical reducer is measured once per pair. The sum is an estimate of the
  component cost, NOT measured model E2E or TPOT. No launch penalty is added.
  Grouped inputs are already compact fixtures; real router/prepare cost is
  outside this unchanged GEMV call and is not presented as free model work.
  Source request footprints are retained separately from hardware counters.
  Default ACU: 20 M8 indexed/BF16 cohorts (5 formats x 4 splits), 3 paired
  rounds each, best screened candidate versus its SAME-recipe baseline.
  Each process has one weight copy, zero graphs, and one direct full call in
  the profiler range; --launch-count 1 selects its producer only. The reducer
  still runs unprofiled for correctness. No cold loop is run under ACU.
  Compare CE cycles and clocks, not old 1.0-GHz timings against new 1.7-GHz
  event times. Neither PASS nor a favorable event median promotes production.

Run on one otherwise idle GPU (requires local pinned actlize git objects)
  PPU_SDK=/usr/local/PPU_SDK CUDA_VISIBLE_DEVICES=1 L2_BYTES=67108864 \
  IDLE_CONFIRMED=1 bash tools/run_simt_split_box.sh

  PROFILE_ACU=0 skips counters explicitly; it is not cycle-based admission.
  Do not set RUN. OUTPUT_ROOT defaults to /workspace. The runner freezes the
  checkout using local git archives; it does not fetch nested submodules.
  No measured wall-time guarantee yet: use reported observed-family ETA,
  including setup/oracle time. ACU progress is reported separately after
  timing. There is no utilization threshold or automatic wall-time kill.

Retry failed/missing cells, preserving completed paired evidence
  RESUME_RUN=/workspace/kpack-simt-split.<actual> \
  PPU_SDK=/usr/local/PPU_SDK CUDA_VISIBLE_DEVICES=1 L2_BYTES=67108864 \
  IDLE_CONFIRMED=1 bash tools/run_simt_split_box.sh

  Resume requires identical frozen source, device, SDK, recipe and image.
  A failing family exits its GPU process; independent families continue.
  Upload the final results=.../review-*.tgz (JSON, logs, resource/ISA text and
  ACU reports, no objects/libraries/weight dumps). Leave the original run for
  retries. Do not delete existing successful evidence or retag it as current.

Local checks before handoff
  Ten PPU object compilations; 96 candidate native entries, FP32 FMA present,
  zero stack allocation. These are compile/static checks, NOT device results.
  Host tests cover partition ownership/direct GGUF partial oracles, unchanged
  math, baseline launch dispatch, source footprints, replay/resume contracts
  and bounded plans. Actual PPU numerical/performance admission remains open.
