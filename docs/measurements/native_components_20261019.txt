Native llama / Quactlize independent-component comparison
========================================================

Contract
--------
All 1544 previously measured points, not a new Cartesian product:
1114 decode + 430 prefill; 810 dense MUL_MAT + 734 indexed MUL_MAT_ID;
Q8_0 and Q2_K through Q6_K. No config sweep and no production change.
Boundary: resident original GGUF weights + F32 activation + GPU expert IDs
to F32 output. Top-k selection, SwiGLU, all-reduce and model scheduling are
outside this operator contract. This is not a model TPOT measurement.

For EACH arm, total = sum of independently measured REAL invocations:
input/quantization/expansion + routing/metadata + producer/provider +
reducer + output. A fused reducer/finish is counted once. Missing components
are not zero; unknown graph nodes fail with their inventory preserved.
Never time three different kernels together and label the span kernel time.

Reuse and supplement
--------------------
The committed historical baseline recovers all 1544 selected costs, including
153 unchanged small-M arms whose timings were omitted from the compact
production table. 150 came from the complete campaign/Q8 review exports;
the other three came from the original five-point decode archive. Archive,
record and source-plan digests remain bound. Their screen evidence is NOT
relabelled as fresh confirmation. Six-round prefill component medians retain
their original evidence. Existing GEMM, SIMT, SF/full expansion, reducers and
adapters are not re-swept.

Two missing responsibilities need device timing:
* GPU row-map creation for 150 indexed prefill points: five unique workloads
  (M=128,512,1024,2048,4096, E=256, top8, channel1). Use the native
  mm_ids_helper already used by the PoC Quactlize caller, not CPU sorting.
* Four-byte per-call error reset for 186 FULL points: one memory-API job.
  active_experts is ALREADY included in FULL measurements; do not add it again.
Thus six supplement jobs per physical worker, not 336 duplicate benchmarks.

Native baseline
---------------
Use the user's existing llama source/build, including pr/kpack-dense. No
branch checkout, caller source patch, K-pack buffer, old six-library bundle,
model or Quactlize runtime rebuild is required. The test compiles one narrow
adapter TU using the exact native ggml-cuda target flags and links the existing
backend kernels. It copies the native HOST dispatcher unchanged; it does not
pick a hand-written MMVQ recipe or force native precision. The four native
cuBLAS call sites are wrapped only to keep those calls OUTSIDE capture.

Warm up the exact native dispatch, then record each custom kernel's actual
parameters. A separate kernel timer repeats only that one stage. cuBLAS is
ordinary per-call CUDA events, never CUDA Graph, retaining every cold-ring
sample and its internal reduction. There is no Asys dependency or invented
host-launch-time correction. Non-kernel capture work is rejected, not erased.

The raw GGUF bytes, activation values and routing match the historical fixture
generators. Weights rotate through at least 2.25x verified L2 in active bytes.
Dequantized B uses distinct storage per copy as well. Resident helpers use
their normal scratch domain. Original GGUF dot checks, full finite-output
checks, full-output comparison with the linked backend on two inputs, omitted
producer and last-weight-copy corruption controls precede timing.

Default 3x3 independent samples; ordinary provider samples include complete
ring traversals. First-use/JIT/warmup excluded. The source, binary, launch,
SDK and physical PCI are recorded. Historical comparison requires the original
SDK/device class (ZW810/72 CUs, 64 MiB L2); another SDK/device is not comparable.
No cross-run median comparison alone proves strict no-regression. Close/noisy
or stale rows require a paired recheck of selected recipes, NOT another sweep.

Run on idle Box devices
-----------------------
Use an existing native PPU Makefiles build from this exact source checkout.
If stale/missing, build with llama's existing .aoneci/scripts/build.sh first;
this test does not silently rebuild llama or change its branch.

(
  set -e
  cd /sim/eec/shared/junfu.qx/quactlize
  git pull --ff-only origin develop
  LLAMA_CI_DIR=/sim/eec/shared/junfu.qx/llama.cpp.ncp \
  LLAMA_CI_BUILD_DIR=/sim/eec/shared/junfu.qx/llama.cpp.ncp/build-ci \
  PPU_SDK=/usr/local/PPU_SDK \
  GPUS=1,2,3,4,5,6,7 L2_BYTES=67108864 IDLE_CONFIRMED=1 \
  bash tools/run_native_components_box.sh
)

Override SDK/build paths with the actual matching installation. The 64 MiB
value is the operator-verified ZW810 value, not a default guess for other GPUs.
Each worker probes physical identity before measurement; aliased cards fail.
Use the existing Python with numpy/gguf; PYTHON can point at that interpreter.
No automatic package installation. No time-limit kill; progress prints every
30 seconds. A full-run duration cannot be promised before measuring fixture
and native-provider wall time on Box.

For resume: rerun the same command with RUN=/workspace/kpack-native-components.XXX.
Completed valid results are retained, even when they show a regression.
Only failed/missing points are retried. A child abort starts the remaining
points in a fresh process; a failed family does not stop other families.
Do not edit source, SDK or backend DSOs during a run/resume. PHASE=pilot is an
optional 32-point diagnostic, never the default/full coverage verdict.
