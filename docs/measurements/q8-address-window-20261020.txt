Counter interpretation / transferable lesson
  At the losing large focus, half-window drops registers78->62 and increases
  active occupancy59.91->83.09%, but cycles increase10.16%. DRAM is essentially
  fixed (44.83584->44.83456 MB), L1/L2 bytes742.94->741.72 MB, VMEM load count
  unchanged. Load-dependency per-issue ratio0.0616->0.3174 and IALU-busy
  ratio0.3826->0.6113 increase. This supports a delivery/scheduling tradeoff,
  not a weight-volume reduction and not exact stall-to-latency accounting.
  Small-focus occupancy stays about11% despite fewer registers; its fixed
  64-CTA grid is still underfilled. Half-window reduces load lookahead as well
  as register lifetime, so lower register count is not a universal win.
  Conversely, the event gains above prevent a blanket "always hoist all B"
  conclusion. Keep window/config/shape as measured axes in the shortlist.
  The address-only focus improvement has fixed registers/loads and virtually
  fixed traffic/instruction counts; exact native dependency attribution is
  still open without the full candidate report/native per-PC evidence.
