# Q4 C4/C8: cold PPU evidence, 2026-09-12

## Scope and authority

PPU-ZW810, M=1, N=8192, K=5120, canonical Q4 K-pack4. Source `6989bf0`.
Archive `q4-cold-geometry-ppu.LPOaqd.results.tgz`, SHA-256
`9b320e2337354828cc8fdf6ee30f69bcef1662aad22d60e10c487a1d95cf03f0`.
Source/image/log/report digests and all 24 timing cells plus 4 ACU reports
were checked. The six alternating rounds each contain 15 event samples.
The weight ring has seven copies of 23,592,960 bytes, exceeding 2.25 times
the verified 64 MiB L2; a graph traverses 35 complete calls. First-use and
graph-upload effects are excluded. This is cold/rotating **weight** timing,
not a model benchmark or proof that A is cold.

| Implementation | Event median, us |
|---|---:|
| Xplane, selected C4/W8 | 22.3062855857 |
| Raw GGUF reference, C4/WN8/WK1 | 22.3885715008 |
| Existing K-pack C4/W8/P4 | 27.7662856238 |
| Candidate K-pack C8/W8/P4 | 23.0005715575 |

C8 reduces latency by 17.1637%; gaps to Xplane/reference are +3.1125% and
+2.7335%. Each paired round is within 5% of both controls. Its maximum
condition-normalized GGUF-dot error is 1.1076865434e-8; zero-code/zero-A and
guard/replay checks pass. All implementations accumulate and output FP32.
Controls reconstruct individual weights in FP16, whereas C4/C8 use FP32
group-affine arithmetic. Do not relabel this as identical rounding.

## What changed

The same `q4_group_affine` body and offline bytes are used. P remains 4,
Warps remains 8, and each CTA has 256 threads. Only Columns changes 4 to 8:

| Quantity | C4 | C8 |
|---|---:|---:|
| Tile N | 16 | 32 |
| CTAs | 512 | 256 |
| K workers | 64 | 32 |
| Passes through 160 K groups | 3 | 5 |
| Last-pass active workers | 32/64 | 32/32 |

Each group of Columns lanes reads adjacent N values. Increasing that group
changes coalescing as well as concurrency and reduction ownership. The source
generator keeps the entire original kernel prefix intact. No AIU, new
offline layout, inter-CTA Split-K, or extra reducer was introduced.

## Imported ACU counters

ACU uses forced-cold replay. Its instrumented durations are not the event
timing values above. Byte units below are decimal MB.

| Counter | C4 | C8 |
|---|---:|---:|
| DRAM bytes read | 23.657 MB | 23.669 MB |
| L1/L2 traffic | 92.381 MB | 47.028 MB |
| L2 transaction count | 1,443,458 | 734,812 |
| Vector load instructions | 163,840 | 163,840 |
| Registers/thread | 56 | 56 |
| Shared bytes/CTA | 512 | 1,024 |
| Achieved occupancy | 84.97% | 43.71% |
| Vector-memory-pipe-busy per issue ratio | 1.645544 | 0.307495 |
| Vector-memory-dependency per issue ratio | 0.500379 | 1.522870 |

The ~49.1% reduction in L1/L2 traffic, with essentially unchanged DRAM bytes
and identical load-instruction count, supports improved transaction packing
and lower issue pressure. It does not justify attributing every microsecond
to one counter. The increased dependency ratio is a reminder that one stall
ratio cannot serve as a universal performance score. Lower occupancy here
coincides with faster execution; maximizing occupancy blindly would be wrong.

By weight-bytes/event-time, modeled bandwidth improves 849.7 to 1025.8 GB/s,
or 31.47% to 37.99% of the user's 2700 GB/s roof. These are not ACU's measured
DRAM bandwidth percentages.

## Transfer limits and reusable entrypoints

- This closes only this M1 Q4 cold shape. Other shapes must retain their own
  historical winner while testing C8; do not substitute it globally.
- The preceding AIU experiment at N5120/K8192 reduced some global-memory
  traffic but introduced substantial synchronization and did not beat the
  current K-pack path. It is not evidence that canonical K-pack requires AIU
  or that direct SIMT loading is inherently insufficient.
- Repository entrypoints: `dev/gemv_ppu/cold_geometry.py`,
  `dev/gemv_ppu/run_cold_geometry.py`, and
  `tools/run_q4_cold_geometry_ppu_box.sh`. The six-shape extension is
  `dev/gemv_ppu/run_cold_shapes.py`; it is a new experiment, not already
  admitted by this case.
- Common checks live in `dev/gemv_ppu/campaign.py::parse_cells` and the
  runner's `validate_entry`. Reuse these before creating another parser.
- ACU metrics used: `dram__bytes_read.sum`,
  `derived__l2_bytes_pipe_l1_total`,
  `derived__kvd_transactions_pipe_l2_total`,
  `ws__inst_executed_op_vmem_ld.sum`, and
  `pu__we_average_warps_issue_stalled_vmem_pipe_busy_per_issue_active.ratio`.
  Definitions are available in the installed SDK's
  `asight/sections/MemoryWorkloadAnalysis_Tables.section`.
