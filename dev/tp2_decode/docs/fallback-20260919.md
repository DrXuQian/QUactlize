# Optimized fallback, not a permanently frozen implementation

Branch: `dev/decode-fallback`, based on the reviewed TP2 experiment.
This branch changes candidate runtime source, not the published runtime pin.
Device integration/performance admission is still pending.

## Selection contract

1. Keep exact measured choices and explicit unresolved exclusions first.
2. A bounded, same-family bucket inherits both the donor's configuration and
   subsequent implementation upgrades. Looking up an old donor and then
   applying upgrades only to the new request's exact N/K left fallback stale.
3. Preserve `QKS_MATCHED_BUCKET` and its `source_n/source_k/source_tokens`.
   Donor timings are not measurements of the new shape. No online tuner, JIT
   search or unconditional TC-to-SIMT rule is introduced.
4. Both exact and bucket choices use the common optimized kernel primitives.
   Unknown dimensions must not imply the oldest reader/reducer/helper.
5. Preserve structural safety fallback: unsupported router semantics, mixed
   TC/SIMT chains, four-byte-only output alignment and incompatible layouts.

The Q8 bucket upgrade uses the existing reviewed replacement registry. New
registry entries therefore improve eligible buckets too; adding another
model-specific condition in the execution code is not required. The bounded
factor-two N/K transfer, token bin, qtype, compute, operator, experts, top-k
and channel family remain enforced. Final ABI query uses the **actual** N/K,
strides, arrangement and workspace size, never donor addresses or sizes.

## Common paths changed

| Path | Candidate fallback behavior | Retained constraint/control |
|---|---|---|
| Q8 selected bucket | Inherit the donor's reviewed vector-reader upgrade, including a reviewed TC-to-SIMT replacement | Same-family, bounded bucket; unresolved stays MISS; predicted label |
| Q8 S1 vector reader | Dynamic N/K hoist for F32-storage/F16-compute dense M1, V5/P4 with C8/W4 or C4/W2,W8 | Existing narrow-window and fixed-dimension winners remain higher-priority exceptions; other compute/M/recipes unchanged |
| Q5 unsigned address and fixed-order fold | Generic BF16/F32 reader V3/C4/W2/P8 no longer restricted to N2048/K512 | Existing fixed incumbent retained; different recipes and arithmetic unchanged |
| SIMT Split-K reducer | All qtypes share ordered float2 reduction of `[row,split,N]` at S2/S4/S8 | Even N/stride, eight-byte bases; scalar fallback for legal four-byte alignment; old Q8 flat M1 winner retained |
| All-SIMT prepare | Default router/identity-map path independent of weight N/K and tokens1..8 | E256/top8, merged all-SIMT mask5, ordinary normalized unbiased router, capacity and gate/down relation |

Q4/Q5 H32 metadata extraction is already common and stays common. The prepare
does not access A or B in its all-SIMT path; removing old weight-size tests
does not change a weight address. SIMT reduction changes vector width, not
FP32 split-add order or output ownership. Hoist changes the lifetime of the
same B loads, not packing or activation precision. Lane ownership remains
`N = tile*Columns*P + (lane%Columns)*P + element`, K worker `thread/Columns`.

Not generalized blindly: Q6's currently winning TC, Q4 paired versus unfused
projection tradeoffs, fixed-dimension compiler specializations, and prefill.
Those still need measured selection. Generic implementation improvements and
globally optimal configuration are different claims.

## Local and device validation

Host checks exercise real dispatcher C ABI with an empty TC catalog: a bucket
upgraded to SIMT must return its actual workspace size without trying to load
or JIT a TC module. They retain donor provenance and reject cross-format,
compute, operator, token-bin and out-of-range transfer. Existing exact-table
and unresolved tests remain enabled. Reducer tests cover M1..8/64, padding,
weak alignment and a wrong `[split,row,N]` negative.

`compile_smoke.cu` instantiates the actual six-format launchers, F16/BF16
branches, aligned reducers and scalar fallbacks. Native inspection verifies
FP32 FMA, fast mantissa-code decoding and vector loads; the row reducers emit
paired loads/stores. Compile the production `execution/moe.cu` separately to
cover both precision-specific prepare dispatchers. None is a device pass.

Next box gate must include requests absent from the exact table, both old
35B and actual TP2 shapes, M1..8 numerics, and complete-call cold timings.
Compare against the **reviewed minimum** from `benchmark.csv`, not only the
original slower production generic baseline. Preserve the frozen experiment
DSOs and previous runtime; publish a new package only with matching receipts.
Do not run the old `prebuilt.json` candidate at this changed source HEAD: use
its original `3b16b5e` source to replay that immutable experiment.

Open work: integrate the reviewed TP2 winners into the exact registry, add the
remaining paired-reader/reduction candidates, and compare the resulting
fallback predictions with the retained winners. Model TPOT/Asys remains a
