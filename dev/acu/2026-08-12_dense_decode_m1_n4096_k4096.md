## The two cells that did not close -- BOTH TRANSCRIPTIONS CONFIRMED BY THE OPERATOR

Re-checked against the screenshots on 2026-08-12: **dp's Block Limit Registers really is 6, and
streamk's achieved occupancy really is 8.05 warp/CU.** Neither is a transcription slip. So in both
cases the disagreement is between the machine and the model above, and the model is the thing that
is wrong or incomplete. This is the checksum doing its job in the direction that is easy to miss: it
did not catch me miscopying, it surfaced two facts no panel states outright.

### 1. dp: 144 regs/thread predicts 7 blocks where the panel reports 6

The occupancy calculator's own "Physical Limit of PPU (8.0)" panel supplies the allocation rules,
so this is no longer guesswork:

    Threads Per Warp 32          Registers per CU 131,072      Max Registers per Thread 256
    Max Warps per CU 64          Max Thread Blocks per CU 64   Max Threads per CU 2,048
    Register Allocation Unit Size 64, granularity: warp
    Shared Memory per CU 262,144, allocation unit 128

which makes the register limit exactly

    regs_per_warp = roundup(R * 32, 64)
    blocks        = floor( floor(131072 / regs_per_warp) / warps_per_block )

That closes on every row it can be tested against:

| arm | R | regs/warp | warp limit | predicted | panel |
|---|---:|---:|---:|---:|---:|
| marlin  | 160 | 5,120 | 25 | **6** | 6 |
| streamk | 256 | 8,192 | 16 | **4** | 4 |
| calculator's own example (R=32, 32 warps/block) | 32 | 1,024 | 128 | **4** | 4 |
| dp      | 144 | 4,608 | 28 | 7 | **6** |

Two things this settles, and one it does not:

* **The earlier "per-thread reserve c = 4" hypothesis is dead.** marlin and streamk both close with
  no reserve at all, and a reserve would break them.
* **streamk really does use 256 registers per thread**, not "at most 252" -- and 256 is exactly
  `Max Registers per Thread`, so that arm is pinned against the hardware ceiling.
* **Warp Allocation Granularity = 8 does not round `warps_per_block` here.** Rounding 4 up to 8
  would give marlin 3 blocks and streamk 2; both panels disagree. Whatever that granularity governs,
  it is not this division.

What remains for dp is a single surviving explanation, now that reserve and granularity are both
excluded: **acu's "Block Limit Registers" column may report the limit after taking the min across
resources rather than the register limit alone.** dp's shared-memory limit is 6, so `min(7, 6) = 6`
is what would be displayed. marlin and streamk cannot discriminate -- their register limits are
already <= their shared limits -- which is why dp is the only row that shows the discrepancy.

**The calculator settles it directly, no device needed**: enter `Threads per block = 128`,
`Registers per thread = 144`, and dp's actual shared bytes per block. If the Registers row reads
`Allocatable Blocks Per CU = 7` while the Shared Memory row reads 6, the report column is a post-min
value and nothing about the register model is wrong.

For the record, the shared side is consistent with this: `BL Shared = 6` requires shared bytes per
block in `(37450, 43690]` and a multiple of 128. A plain accounting of the config -- A `16*128*2*3 =
12288`, B at int4 `128*128/2*3 = 24576`, scales at gs=128 `128*2*3 = 768` -- totals 37,632, which is
in the window and is `294 * 128` exactly.

### 2. streamk: half the machine is idle for half the elapsed time

    residency ceiling = 288 CTAs * 4 warps / 72 CU = 16.00 warp/CU
    BL Regs = 4 -> 4 CTAs/CU * 72 CU = 288 slots, so ALL 288 CTAs fit resident at once
    achieved                                       =  8.05 warp/CU

Confirmed real. Since every CTA can be resident from the start, the factor of two is not an
admission limit -- it is a time average, and it says streamk's warps occupy the machine for roughly
half of its elapsed cycles. The obvious candidate is the two-phase structure (work, then the
fixup/reduce phase draining) but that is a hypothesis, not a reading; the partition analysis owns it.

Note the contrast that makes this worth keeping: dp and marlin sit at 1.78/4.00 against ceilings of
1.78/4.00 -- **they are one wave with no turnover at all**, every CTA resident start to finish.
streamk is the only arm whose achieved occupancy is not simply its grid size.
